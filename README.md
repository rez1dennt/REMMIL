# REMMIL — Основа прочных решений

Одностраничный сайт на HTML, CSS и JavaScript по утверждённому варианту «Кремовый и приглушённый синий».

## Открыть сайт

Откройте `index.html` в браузере. Интернет и установка зависимостей для просмотра не нужны: изображения и стили находятся в проекте.

Для локального сервера с Node.js:

```sh
npm start
```

Адрес выводится в терминале. По умолчанию — `http://127.0.0.1:4173`.

## Что находится в проекте

- `index.html` — вся страница, базовое содержимое и метаданные.
- `css/styles.css` — палитра, сетки, адаптив и анимации.
- `css/ordering.css` — объёмная секция заказа, иллюстрации, соединяющая линия и адаптив шагов.
- `js/content.js` — товары, описания, характеристики, цены, документы и настройки контактов.
- `js/model.js` — логика отбора товаров, валидации и форматирования.
- `js/phone-mask.js` — маска телефона, редактирование по цифрам, вставка, удаление и отмена ввода.
- `js/legal-config.js` — реквизиты оператора, версия согласия и место для домена.
- `js/site-shell.js`, `js/privacy.js` — общее меню страниц и локальные настройки конфиденциальности.
- `privacy.html`, `consent.html`, `cookies.html`, `requisites.html` — юридические страницы.
- `js/app.js` — каталог, вкладки, меню, FAQ и форма.
- `assets/` — локальные оптимизированные изображения WebP, шрифты Lora/Manrope с лицензиями, тонкий фоновый рисунок и favicon.
- `assets/reference/approved-design.png` — утверждённый визуальный ориентир.
- `tests/` — проверки логики и браузерные сценарии.
- `qa/` — снимки экрана и результаты последней проверки.

## Изменить товары и тексты

Редактируйте `REMMIL_CONTENT.products` в `js/content.js`. Каждая запись содержит:

- `id` — уникальный идентификатор;
- `category` — `adhesives` или `primers`;
- `name`, `short`, `description`, `details` — название и тексты;
- `image` — путь к изображению;
- `price` — число, рубли;
- `packaging` — подпись фасовки;
- `consumption` — объект `{ value, notes }`: расход материала и условия, влияющие на него;
- `descriptionSections` — массив `{ title, text }`: назначение, состав, подготовка основания, нанесение и хранение;
- `comparisonPurpose`, `composition`, `comparisonPackaging` — данные сравнения;
- `documents` — массив документов.

Новые записи автоматически появляются в каталоге, фильтрах и сравнении. Для документа:

```js
documents: [
  { title: 'Технический лист МС-90', url: 'assets/documents/mc90.pdf' }
]
```

При загрузке открыто «Описание». Расход виден сразу, подробности представлены закрытыми раскрывающимися разделами. Одновременно открыт один раздел. «Сертификаты» — отдельная рабочая вкладка. После изменения данных или стилей запускайте `npm run build`: он обновляет исходное описание В-90 для режима без JavaScript, юридические страницы, серверный каталог и хеши CSS/JS в HTML. Хеши предотвращают смешивание устаревших файлов из кеша с новой разметкой.

Документы конкретного состава выводятся над общим свидетельством на товарный знак REMMIL № 1251523. При пустом массиве остаются свидетельство и предложение запросить технические документы у менеджера. Свидетельство доступно как превью, полное JPG и неизменённый исходный PDF в `assets/documents/`; оно относится к бренду, а не к качеству отдельного состава. Для просмотра без JavaScript в HTML оставлены базовые сведения о трёх исходных продуктах и ссылки на свидетельство.

Логотип в шапке — прозрачный вектор `assets/remmil-logo.svg`, в подвале — `assets/remmil-logo-light.svg`. Контуры знака и букв перенесены с оригинала из PDF; для светлой поверхности надпись выполнена в цвете заголовков сайта, для тёмной — в светлом. Оригинальное изображение сохранено в `assets/reference/remmil-logo-original.jpg`. Источники описаний МС-90, PUR-2R В-90 и грунт-покрытия записаны в `docs/product-sources.md`.

## Телефон и форма

В `js/content.js` замените `phone` и установите `phoneIsDemo: false`. Ссылки автоматически станут звонками на рабочий номер.

Поле телефона форматирует российский номер в `+7 (999) 123-45-67`, принимает вставку с `8`, `+7` или десятью цифрами. Backspace и Delete проходят сквозь скобки и дефисы; работают выделение, вставка, вырезание и отмена ввода. Проверка выполняется при выходе из поля и отправке: имя содержит минимум две буквы, номер заполнен полностью, очевидные повторяющиеся заглушки отклоняются. Проверка не подтверждает существование номера.

Подготовлен PHP-обработчик `api/lead.php`, адрес уже указан в `formEndpoint`. Он принимает имя, телефон, материал, идентификатор запроса и отдельное согласие. Успех возвращается только после передачи письма SMTP-серверу. Настройки SMTP находятся в игнорируемом файле `private/remmil-mail.php`, вне публичной директории хостинга. В репозиторий включён только пример конфигурации. Получатель — 2009-parketdok@mail.ru. PHPMailer включён в исходники, Composer на хостинге не требуется.

Подробная инструкция по размещению — в `docs/php-hosting.txt`. В подготовленном для клиента архиве папки `public_html` и `private` располагаются рядом; SMTP-настройки уже заполнены. В статическом Node-preview и GitHub Pages PHP не выполняется, поэтому форма сообщает о неотправленной заявке. Внешняя отправка не проверялась по просьбе пользователя; проверки используют локальный SMTP.

Сервер повторно проверяет поля и согласие, ограничивает частоту запросов, отсеивает скрытое поле для ботов и защищает от дублирования запроса. Записи согласия хранятся в закрытом `private/storage`, срок — 90 суток. Приём запроса фиксируется серверным временем. Для ежедневного удаления без новых запросов предусмотрен `private/cleanup.php`.

Порядок юридической настройки описан в docs/legal-handoff.md. После изменений запускайте `npm run build`.

## Проверки

```sh
npm install
npm run build
npm test
npm run test:php
npm start
```

В другом терминале, с запущенным сервером:

```sh
# PowerShell: укажите адрес действующего сервера
$env:TEST_URL = 'http://127.0.0.1:4173'
npm run test:browser
```

Браузерные проверки используют установленный Google Chrome и Playwright. Проверяются адаптив 320–1440 px, фильтры, товары, вкладки, меню без сдвига страницы, FAQ, форма, ресурсы, доступность и добавление новой позиции через файл данных.

Клиентская часть — автономные HTML/CSS/JavaScript. Команда build синхронизирует статические данные и версии ресурсов; бандлер и фронтенд-фреймворк не используются. `test:php` требует PHP в PATH и проверяет реальную цепочку браузер → PHP → локальный SMTP, не отправляя внешние письма. `package:hosting` подготавливает закрытый комплект с локальной конфигурацией; этот комплект не публикуется в GitHub.
